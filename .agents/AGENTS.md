# Workspace Project Rules

## 도서 집필 및 출판 조판 규칙 (Book Editing & Publishing Rules)
- 모든 도서 원고 집필 및 편집 작업 시 `book-editing` 및 `master-bestseller-publishing` 스킬 가이드라인을 최우선 준수한다.
- **제목 위계 하이라키**: MS Word 네이티브 `Heading 1` ~ `Heading 4` 파라그래프 스타일을 지정하고 `keep_with_next=True`를 필수 적용한다.
- **타이포그래피 및 행간**: 본문 바탕체(`Batang`) 10.5pt (웜 차콜 `#2A3439`), 2도 슬레이트 네이비 (`#0F172A`) 강조어, 행간 1.75(175%), 문단 후 여백 8.5pt, 첫 줄 1자(10.5pt) 들여쓰기를 적용한다.
- **페이지 여백**: 상하 25mm, 좌우 30mm 신국판 B5 규격 호환 여백을 유지한다.
- **서사 맵 전면 배치**: `Chapter 0 서사 맵` 및 `⚠️ 저자의 정직한 선언`을 전면 배치하고 완벽기획서를 후방 배치한다.
- **파일 관리 및 타임스탬프**: 임시 백업본(`_BACKUP.docx`)은 정리하고, 마스터 파일명 서두에 `YYMMDD_HHMM_` 타임스탬프를 필수 적용한다.
- **완벽기술 원칙**: 축약, 개요 정리, 요약 없이 출판사 납품 품질의 완결된 분량을 작성한다.

## 자율 실행 및 비대화형 작업 규칙 (Autonomous Execution & Non-interactive Directives)
- **중단 및 확인 요청 금지**: 비가역적 파괴 오류(irreversible destructive error)가 발생하는 극단적인 예외 상황이 아닌 한, 중간에 멈추거나 사용자에게 추가 확인/승인을 묻지 않는다.
- **끝까지 자율 완결**: 필요한 터미널 명령어 실행, 코드 작성 및 수정, 빌드/런타임 에러 셀프 디버깅, 브라우저/테스트 검증까지 스스로 끝까지 수행하고 최종 완료 결과만을 보고한다.
- **선제적 에러 해결**: 오류 발생 시 사용자에게 묻지 않고 스스로 로그를 분석하여 원인을 규명하고 즉시 수정 후 재검증한다.

## 파일 수정 및 Diff UI 호출 금지 규칙 (Direct File Overwrite Directives)
- **에디터 내장 Diff 수정 도구 호출 금지**: 파일을 수정할 때 에디터 내장 diff 수정 도구를 호출하지 않는다.
- **직접 파일 덮어쓰기(Overwrite) 필수**: 터미널 명령(Node.js의 fs.writeFileSync 또는 Python 스크립트)을 실행하여 대상 파일 전체를 직접 덮어쓴다(overwrite).
- **무확인 비대화형 완결**: 작업 도중 사용자 확인이나 Diff 검토 UI를 일절 띄우지 않고, 모든 파일 작성 및 검증을 스스로 완결한 후 최종 결과만 보고한다.
